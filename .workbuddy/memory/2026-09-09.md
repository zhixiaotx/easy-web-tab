## 云同步：外部工具（备份编辑技能）改云端后点同步不生效 —— 根因与修复
- **实证诊断**（读 `C:\Users\YangLiJuan\Nutstore\1\easy-web-tab\`）：5 个信封 `pushedAt` 全部停留在 `1788819841207`（9-08 06:24），但 `nav.json` 的**文件 mtime = 9-08 16:42**（技能改过）。证明**技能写入只更新条目 `updatedAt`，从不更新信封 `pushedAt`**（`add_entry.py` 里无 pushedAt 逻辑）。
- **根因**：`pullNow` 里 `remoteTs = max(pushedAt, Last-Modified)`，判定分支 `dirty && remoteTs <= localTs` → **直接跳过、保留本地**。外部工具写云端时 pushedAt 不更新，一旦 Last-Modified 缺失/不可信（或 localTs 已被之前的 cancel/同步推高），remoteTs 就是旧值 → 命中跳过分支 → 技能修改被**静默丢弃**，表现为"点同步没生效"。
- **次生问题**：静默合并（diff<500）分支只 `importRemote(merged)` 写本地，**不回推云端**，且末尾 `clearDirty()` → 合并结果永远不上云、其他设备拿不到，下次 pull 重复触发。
- **修复（useCloudSync.ts + AppSettingsDialog.vue）**：
  1. 引入 `timestampsReliable = pushedAt > 0 && lastModifiedMs > 0`；`lastModifiedMs === 0` 时 remoteTs 退化为 `Date.now()`。合并分支条件改为 `dirty && (remoteTs > localTs || !timestampsReliable)` —— **时间戳不可信时绝不静默跳过**（走到这里已确认内容 hash 不同）。
  2. 新增 `mergedAny`：静默合并后在 `clearDirty()` 之后补一次 `pushNow(true)` 回推 merged（merged 是 union，不丢数据）；toast 提示"已合并云端变更并回传"。
  3. 新增导出 `forcePullRemote(silent)`：忽略 dirty 与时间戳，无条件用云端 5 份覆盖本地，`maxTs` 用 `Date.now()` 兜底保证 lastSyncAt 前进。
  4. 设置弹窗云同步区新增「以云端覆盖本地」按钮（`sync-force-pull`，带 confirm 二次确认 + 说明文案），handler `handleForcePull`。
- **未改（有意保留）**：`mergeWorkbench` 的 `settings: local.settings` 与 `mergePrefs` 标量键本地优先——技能只改业务数据（站点/待办/便签/倒计时/记账等），不碰 settings，故非本次问题；改动风险高于收益。
- 验证：`vue-tsc -b` EXIT=0、`vite build` EXIT=0 通过。中途连续 3 次因**环境内存耗尽**（native `Zone Allocation failed` / EXIT=3·127）失败，非代码问题，重试即可（本环境高峰期常见，`--max-old-space-size=3072` 相对稳）。
- 排查手法沉淀：定位"云同步不生效"这类问题时，**先读坚果云本地同步文件夹里 5 个信封的 `pushedAt` 与文件 mtime 对比**，能立刻区分"程序推送的"与"外部工具改的"，比读代码猜快得多。
