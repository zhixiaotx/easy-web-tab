## Bug 修复：密码更新后云同步不了（原因 1/2/3 一并修）

**根因（密码是整库单密文，这是所有约束的源头）**
`savePasswords()` 用 `encrypt(JSON.stringify(passwords.value), masterPassword)` 把**整个密码库加密成一个密文串**再 `idbPut('passwords', ...)`。由此：
- 密文层面**无法条目级合并**（不像 todos/notes 可按 id+ts 并集）
- 用远端密文整体覆盖本地时，若两端主密码不同 → 本地主密码解不开 → **不可恢复**

**修复 1（静默失败）** `passwords.ts`
- `savePasswords()` 返回 `boolean`；`!currentMasterPassword` 时 `console.warn` + `return false`（原来直接 `return`，不写库/不 markDirty/不报错）
- `addPassword`/`updatePassword`/`deletePassword` 改为 `Promise<boolean>`；`updatePassword` 的 `index === -1` 也返回 false
- `importPasswords` 返回值新增 `saved: boolean`
- `WorkbenchPassword.vue` 的 `handleSave`/`handleDelete` 检查返回值，失败时 `toast.error('…密码库已锁定，请重新解锁后重试')` 并 **return 不关表单**（保留用户输入）
- 触发场景：P0-3 的 5 分钟空闲自动锁定（`IDLE_LOCK_MS = 5*60*1000`）后未重新解锁 → 保存被守卫静默吞掉

**修复 2（静默合并吃掉远端更新）** `useCloudSync.ts`
- 新增 `passwordsDiffer(local, remote)`：比较 `local.passwords !== remote.passwords`
- `pullNow` 两处 `diffSize < MODULE_DIFF_THRESHOLD` 的**静默合并**分支加 `&& !passwordsDiffer(...)` → 密码有差异时改为弹冲突框交用户决策
- （`mergeData` 的 `passwords: local.passwords` 保留不变——密文无法合并，这是技术硬约束）

**修复 3（`!dirty` 被远端整体覆盖）** `useCloudSync.ts`
- `!dirty` 分支：若 `passwordsDiffer` → 走 `mergeData(localExport, remote)` 保留本地密码 + `toast.warning` 提示可改用「云端覆盖本地」；否则照常 `applyRemote(remote)`
- 保留了"坚果云手改 backup.json → 拉取"的目标场景（其他模块仍整体拉取）

**验证**：`vue-tsc -b` EXIT=0；`vite build`（Temp）EXIT=0。改动未提交。

**遗留（未做，需评估）**：若想真正支持密码条目级合并，需把存储改为**逐条加密 + 嵌入 salt**（可参考 `exportEncryptedPasswords()` 里 `${saltHex}|${cipher}` 的格式），属数据结构迁移，风险较高，单独立项。

## 优化：云同步提示过频 —— 后台自动同步全部静默（`useCloudSync.ts`）

**根因**：后台自动同步走的是**非静默**路径，用户什么都没点也会弹 toast。两个触发器：
- 定时轮询 `startInterval` → `syncNow()`（默认 silent=false）
- `visibilitychange` 页面重新可见 → `pullNow()`（无 silent 参数）
加之 `pullNow` 内部 `!dirty` 分支的 `applyRemote(remote)`、远端无备份时的 `pushNow()` 均未传 silent，于是每次轮询/切标签页都弹「云同步完成」。

**做法：区分「用户主动」与「后台自动」**
- `pullNow(silent = false)`、`syncNow(silent = false)` 新增 silent 参数（与既有 `pushNow(silent)`/`applyRemote(silent)` 风格一致）
- 内部提示点全部受 silent 约束：`applyRemote(remote, silent)`、`pushNow(silent)`、拉取出错改 `if (silent) console.error(...) else toast.error(...)`
- 触发器改静默：`startInterval` → `syncNow(true)`；`visibilitychange` → `pullNow(true)`
- 三个手动入口（HomeView / WorkbenchView / BusinessView 的 `handleSyncNowClick`）**保持非静默**——主动操作需要明确结果

**两条刻意保留的非静默提示**
1. `applyRemote` 中 `identityChanged`（远端密码身份与本地不同）→「云同步完成，密码面板已锁定，请输入来源设备主密码解锁」。**不受 silent 约束**：它不是"同步成功"的例行播报，而是解释"面板为什么锁了"，静默会让用户对锁屏一头雾水。
2. 冲突警告（`dirty && diffSize >= 阈值` 两处）→ 必须用户决策，冲突弹框 + 提示都保留。

**静默失败不会丢感知**：`status` 置 'error'、`errorMessage` 落值，同步按钮有 `wb-sync-btn-error` 红态 + 文案「同步失败」；用户点「立即同步」即可看到具体错误 toast。

**保留未改**：密码增删改后的「…成功，已同步到云端」——属于用户主动操作的直接反馈，去掉会让人不知道有没有上云。若仍嫌频繁可再收敛。

**验证**：`vue-tsc -b` EXIT=0；`vite build` EXIT=0（`✓ built in 1.88s`）。
