## 云同步：技能改云端后「拉下来又变回去」——根因诊断

### 现象
用户用备份编辑技能改云端数据 → 点同步后**确实看到**了新数据 → 过一会儿刷新，数据变回修改前的旧值。

### 实证诊断（关键证据链）
1. **识别技能写入痕迹**：云端 `workbench.json.bak.20260909-233931` 的命名格式 `{src}.bak.{YYYYMMDD-HHMMSS}` 与技能 `add_entry.py` 的 `do_backup()` 完全一致 → 昨晚 23:39:31 是**技能**在改 `workbench.json`（不是程序 push）。
   - 比对 .bak 与当前：ledger 24 → 25 条，新增 `ld_20260909_233931_b073`「换电瓶 450」，createdAt = 23:39:31 ✓
   - 技能 `make_id()` 格式 `ld_YYYYMMDD_HHMMSS_xxxx` 与程序一致，**无法用 id 格式区分**（只能靠备份文件/时间戳判断）。
2. **本地与云端对照**：云端 25 条（含技能数据）；本机 Edge `http_localhost_16718.indexeddb.leveldb/000003.log` 搜「换电瓶」**搜不到**（UTF-8 与 UTF-16LE 均搜过，对照词 `categoryId` 能搜到）→ **本地 IDB 当前不含该数据**。
   - 应用实际跑在 **Edge**（不是 Chrome）；Chrome 的同名 IDB 停在 09-08，是旧的。
   - 诊断手法：`ls -dt <IndexedDB>/*.leveldb`（按 mtime 找活跃库）+ `grep -ralP` 搜 UTF-16LE 字节序列。

### 根因
`pullNow` 的分支判定（useCloudSync.ts ~1168-1192）：
```
dirty && (remoteTs > localTs || !timestampsReliable)  → 合并/冲突
dirty && remoteTs <= localTs                          → 跳过（保留本地）  ← 元凶
!dirty                                                → 落地
```
- `localTs` 取自 `LAST_SYNC_KEY`，而它在 **pushNow 成功后被写成 `Date.now()`**。
- 技能改云端**只更新文件 mtime、不更新信封 pushedAt**（pushedAt 恒为 09-07 旧值）→ `remoteTs = max(pushedAt, lastModified) = 技能改文件时刻`。
- 于是：**只要本地在技能改文件之后推送过一次，`LAST_SYNC_KEY` 就大于 remoteTs，此后所有 pull 都命中「跳过」分支** → 云端外部修改永远拉不下来，刷新后显示本地旧数据。
- 昨晚我加的 `!timestampsReliable` 兜底**救不了这个场景**：此时 pushedAt 与 lastModifiedMs 都 > 0，`timestampsReliable = true`，仍走跳过分支。
- 另：若曾经落地过（reload 后 UI 显示新值），随后本地**旧内存**被某个 save 写回 IDB，也会表现为「看见又变回」——两条路径都指向「本地优先压过云端」。

### 修复方案（已确认并实施，单文件 `src/composables/useCloudSync.ts`，+116/−7）

1. **每信封单独记录云端 mtime**（新增 localStorage `ewt.cloudSync.remoteTs.<file>`，容差 60s）：
   - `externallyModified = lastModifiedMs > 0 && (known === 0 || lastModifiedMs > known + 60s)`
     → 命中即强制进入**合并（union）分支，绝不跳过**，且不再与本地推送时间 `localTs` 比大小。
   - `known === 0`（新设备/老版本升级）也判为可能外部修改 → 老用户升级后首次同步就能拉到云端数据（否则首次仍会 skip）。
   - 落地/合并成功后 `writeRemoteTs()` 推进基线；`pushNow` 成功后写 `pushedAt`；`forcePullRemote` 写云端 mtime。
   - 内容 hash 相同时也更新基线（避免下次失真）。
2. **推送保险**（用户要求）：新增轻量 `webdavHead()`（`DavMethod` 加 `'HEAD'`，避免每次推送前全量 GET 3MB+）
   + `detectExternalChange()`。命中 → 中止盲推，改调 `pullNow(silent)` 先合并（union 不丢本地），由其内部回推上云。
   - `pushNow(silent, skipRemoteGuard)` 新增第二参数：`pullNow` 合并后的回推、冲突裁决后的推送传 `true`，
     避免 pull→push→pull 递归。
   - HEAD 不可用/探测异常 → 降级为原行为（不阻断业务推送）。
3. **验证**：10 条断言脚本全通过（含反向对照：证明旧逻辑在本场景确实落到 `skip` 分支），脚本已删。
   `vue-tsc -b` EXIT=0、`vite build` EXIT=0。
