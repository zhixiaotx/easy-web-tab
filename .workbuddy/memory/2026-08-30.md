## 主页卡片排序修复：永久调整 + 立即云同步（Lucky 反馈「位置不对 + 刷新就恢复 + 要立即云同步」）
Lucky 反馈三处问题：(1) 调整后位置不对；(2) 刷新就恢复（没保存）；(3) 要永久调整且调整后立即云同步。

**根因**
- 「位置不对」：`cardStyle` 仅当 `o` 有值才输出 `style.order`，未自定义的卡 `order:0`；拖 A→B 后只 A/B 有正 `order`，其余 `0` → 网格按 `order` 升序把 A/B 挤到整屏末尾，而非原地互换。
- 「刷新就恢复」：① 持久化本身通的（`settings` 是 IDB 核心库，`persist()` 写、`initSettings` 读回、云同步也导出）；② 真正让刷新像恢复的是「松手必须精确压在另一张卡上才 `reorderCard` 落库」，落在网格空隙则 `drop` 目标是容器而非卡 → 不保存 → 刷新回原序；③ 叠加上面的渲染 bug，即便存了也渲染到末尾。
- 「立即云同步」：`persist()` 只 `markDirty()`，真正推送要等手动/定时/切标签页。

**改动**
- `useHomeLayout.ts`：新增 `effectiveOrder(id)`（`o` 优先，否则容器内默认序号）；`cardStyle` 始终输出 `order = effectiveOrder` → 全部卡 order 基线一致，交换两张即正确互换、刷新后渲染一致。新增 `handleContainerDragOver('容器',$event)`（松手在空隙时取光标最近卡片写入 `dragOverId`）+ `handleContainerDrop('容器')`（按最近卡 `reorderCard`）；导出 `effectiveOrder/handleContainerDragOver/handleContainerDrop`。新增 `scheduleCloudPush()`：开启云同步时拖完 600ms 防抖动态 `import('@/composables/useCloudSync')` 静默 `syncNow(true)`（不弹 toast），根因是 `reorderCard` 末尾调用。

## 缺陷修复：顺序调整后「被云同步恢复」（Lucky 反馈「调整完立马被云同步恢复，应调整后直接推送」）
上一节 `scheduleCloudPush` 用 `syncNow(true)`（先拉后推）。`pullNow` 在 `dirty && remoteTs<=localTs` 静默合并分支会先 `applyRemote(merged)`（`applyRemote` 内 `reloadAllStores` 后 `clearDirty()`）→ 再 `pushNow(true)`。若这一步 pushNow 因瞬时网络/WebDAV 失败，dirty 已被清空、云端仍是旧顺序；后续后台拉取（visibilitychange / 轮询）命中 `!dirty` 分支 `applyRemote(remote)` → 用旧顺序覆盖本地，表现为「调整完立即被云同步恢复」。

**改动**：`useHomeLayout.ts` 的 `scheduleCloudPush()` 改为动态导入后调 `pushNow(true)`（只推不拉），不再 `syncNow`。纯 push 的语义：成功→云端已含新顺序且 clearDirty、LAST_SYNC_KEY 更新，后续拉取 contentSame 走 noop；失败→dirty 保持置位、本地不被覆盖，下次自动同步仍走 dirty 分支保护本地。完全贴合 Lucky「调整后把信息推送出去」的诉求，且不会再被拉取覆盖。

**验证**：`vue-tsc -b` EXIT=0。

**待 Lucky 实测**：开启云同步后拖卡→看 `backup.json` 的 `settings.homeCardLayout.o` 是否即时更新（不再回退旧顺序）。

**关键陷阱（务必记住）**：`store.setHomeCardLayout` 的语义是「patch 中**缺失**的字段会被 `delete`」。若直接传 `{ w: 3 }` 会把该卡已有的 `h` 和**用户拖出来的排序 `o` 一并清空**。故 `setCardSize` 必须：① 先 `const next = {...cur}` 带上现有布局；② 用 `'w' in patch` 判定"要不要改这一项"，而不是判 `undefined`（只有显式传 `{w: undefined}` 才表示"清除该项"）。同理 `resetCardSize` 传 `{ o: cur.o }` 而非 `{}`，才能"只清宽高、保住排序"。已用 8 条断言脚本验证该不变量（改宽保留 o、改高保留 w+o、宽度 clamp 到列数、清空只删该项、清空末项则移除整条记录、恢复默认保留排序），全部通过后删除临时脚本。

**现状**：`resetHomeCardLayout`（store 里整包清空、连排序一起清）仍是死代码未调用——尺寸区块的「恢复默认」刻意只清 w/h 保排序，故不复用它。
